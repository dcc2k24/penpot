# Backend MCP

Backend-native MCP: MCP tokens call RPC commands in the backend. Code: `app.rpc.commands.mcp`, `app.rpc.commands.mcp-write`, `app.rpc.commands.mcp-limits`, `app.rpc.mcp-scope`, `app.http.session` (render sessions).
Contract doc (may be rewritten; read it, do not copy it): `mcp/docs/backend-mode-contract.md`.
Token rules, including the one-token-per-OAuth-client rules: `mem:backend/auth-permissions-product-domains`. TS server modes: `mem:mcp/core`. Shared flags and types: `mem:common/core`.

## Flags

- `enable-mcp-backend` (`:mcp-backend`): off by default. Off: an MCP token reaches only `send-mcp-feedback`; other MCP commands answer `:mcp-backend-disabled` (`:restriction`). `rpc.clj` `wrap-authentication`.
- `enable-mcp-raw-changes` (`:mcp-raw-changes`): off by default. Gates `mcp-apply-changes` only: `:mcp-raw-changes-disabled`.
- Flags are declared in `common/src/app/common/flags.cljc` (`varia` set). Tests turn them on in `backend/test/backend_tests/helpers.clj`.

## Dispatch

- Every command with `::rpc/token-type "mcp"` or `::rpc/allow-token-types #{"mcp"}` is refused with `:mcp-backend-disabled` while the flag is off. The exception is `::rpc/mcp-bridge` (`send-mcp-feedback`).
- Profile switch: when the profile prop `:mcp-enabled` is `false`, every MCP-token call is refused with `:mcp-disabled` (`:restriction`), whatever the command. The bridge is exempt. This check runs before the flag check. The token lookup reads the state once per request (`profile-state`, `http/access_token.clj`), not once per call in `rpc.clj`. A profile row that cannot be read counts as off.
- `::rpc/token-type "mcp"`: only MCP tokens may run it. Sessions and personal tokens get `:token-auth-required`.
- `::rpc/allow-token-types #{"mcp"}`: MCP tokens may run it next to sessions and personal tokens. Scope is checked only for MCP tokens.
- Scope check: `wrap-mcp-scope` (`rpc.clj`), inside params validation. Sessions and personal tokens skip it.
- A command with MCP metadata and no `::rpc/mcp-scope` fails at startup (`check-mcp-scope!`). There is no default by name prefix.
- Refusals (flag and scope) are logged and counted by `note-refusal!` (`rpc.clj`).

## Scopes

- Scopes are `mcp:read`, `mcp:write`, `mcp:manage`, `mcp:delete`. Stored as `mcp:*` strings in `access_token.perms`. `app.rpc.mcp-scope`.
- A token with no `mcp:*` entry holds `mcp:read` only. New tokens start that way.
- Any scope implies `mcp:read`. `write`, `manage` and `delete` do not imply each other.
- Grant: OAuth approval calls `grant-client-mcp-scopes`. The hand-made token's scopes change through `update-mcp-token-scopes`, which uses `replace-scopes` (`mcp_scope.clj`). Both are in `access_token.clj`. Unknown `mcp:*` values are dropped (`effective-scopes`).
- Missing scope: `:mcp-scope-required` (`:authorization`).

## Render sessions

- Made by `create-mcp-render-session` (`mcp:read`). The session props are `:mcp-render {:file-ids ...}` (the file and its libraries) and `:token-id` (the minting token). Lifetime 10 min (`mcp-render-max-age`, `http/session.clj`).
- Restricted: only routes with `::session/allow-restricted` see them. Those routes are `/api/main/methods`, `/api/management/methods`, `/api/rpc/command` (`rpc.clj`) and `/assets` (`http/assets.clj`). Every other route sees no session.
- Never renewed while restricted.
- Media: the file-media handler (`generic-handler`, `render-covers?` in `http/assets.clj`) serves a render session only the media of the files its `:file-ids` name: the file and its libraries. Other media answers 404.
- Die with their token: each use checks that the `access_token` row exists and is not expired. No `:token-id` fails closed.
- Die when MCP is off for the profile: the token lookup reads profile prop `:mcp-enabled` on each request. No profile row fails closed.
- Age: refused at 10 min. The session GC (`sql:delete-expired-v2`) deletes them once `created_at` is past 10 min. The GC runs on the daily cron, so the row can outlive the age, but auth refuses it at once. See `mem:backend/session-expiration`.

## Write path invariants

- One transaction per call (`::db/transaction true`). Every batch of one call commits in it.
- File lock: `SET LOCAL lock_timeout = '15s'`, then `xact-lock!` and the share lock on the file row (`load-write-file`). A lock wait over the limit (SQLState 55P03) is a `:conflict`: `:mcp-file-busy` for the file lock, `:mcp-lock-timeout` for any other lock wait inside the write (`lock-wait!` wraps the whole write). Only writes lock; dry runs do not.
- File decoded once (`begin-batches!`), written once (`finish-batches!` through `bfc/update-file!`). Each batch gets its own change row and revn (`apply-batch!`).
- Project row is updated last, just before the commit.
- Batches: a batch holds at most 2000 compiled changes of any kind (`notify-changes`). A call above 2000 changes, or with `allow-split`, is cut into batches (`batches-of`) at whole-operation edges (`split-batches`): an operation is never split, and one above 2000 gets a batch of its own. The layout reflow gets its own batch or batches when it would cross the bound. Max 50 batches per call (`:mcp-too-many-batches`, checked before the first write).
- Time budget: 60 s. Checked before each batch after the first. Over budget: `:mcp-time-budget-exceeded` (`:validation`). The transaction rolls back.
- Snapshot: one per call, taken with the first batch and never on a half-applied state. Rule: deletes always (delete types, and token changes with no `:attrs`), more than 100 operations or changes, or `snapshot: true` forces it; `snapshot: false` drops only the size rule. Keep 20.
- Validation forced: the affected-shape check always runs. The schema check runs for raw changes (`mcp-apply-changes`). Not a user flag.
- Dry runs: never write. They load read-only, skip the lock and return the validation result.
- Refused change types: `set-tokens-lib`, `purge-component`, `purge-typography`, `purge-color` (`:mcp-change-type-refused`).
- Media: must be in the file or a readable library (`:mcp-foreign-media`).
- Loader: `compile-ops!` binds `pmap/*load-fn*` to `feat.fdata/load-pointer-of-files` over the file id and its library ids, so a library page loads only when an operation reads it. Libraries come from `files-update/library-files`, each decoded with its pointers unloaded. The update path (`files_update.clj`) binds `pmap/*load-fn*` to `bfc/pointer-loader` for its own file.
- Revn: `base-revn` older than the stored revn gives a `revn-lag` warning. `fail-on-conflict` raises `:mcp-revn-conflict` when the overlap is not empty or the read was cut short.
- Webhooks and audit: a real write names its event `update-file`, batch key file, timeout 2 min. A dry run or a replay names no event. Metrics and the log line come after commit.
- Commit errors from `begin-batches!` keep the generic codes: `:vern-conflict`, `:revn-conflict`.
- Batch errors carry `:revn-before-call` (the file revn when the call started), `:failed-change-index`, and `:failed-operation-index` and `:failed-operation-last-index` when the batch holds an operation.
- `:conflict` errors answer HTTP 409, with `:state`, `:path` and `:context` removed (`app.http.errors`, `handle-error :conflict`).

## Limits

- Rate limits (`backend/resources/rlimit.edn`, key `<profile-id>.mcp` from `rlimit.clj` `get-uid`; bucket is capacity/refill/interval):
  - `:mcp-read` `1200/600/1m` for the read commands.
  - The six new reads (`get-mcp-subtree`, `get-mcp-interactions`, `find-mcp-connectors`, `get-mcp-fonts`, `get-mcp-page-lint`, `find-mcp-similar-boards`) are in the `:mcp-read` list of `rlimit.edn`, with the other reads.
  - `:mcp-write` `600/300/1m` for the three write commands.
  - `update-mcp-token-scopes` uses `:access-token` `60/30/1m`.
- Concurrency (`backend/resources/climit.edn`, `app.rpc.climit`):
  - `:mcp-apply/by-profile` 1 permit, queue 5, timeout 60 s.
  - `:mcp-apply/global` 6 permits, queue 50, timeout 60 s.
  - `:mcp-apply/by-team` 4 permits, queue 50, timeout 60 s. Refusals name the limit in the `climit` metric and in the 429 body (`type` `concurrency-limit`, `code` `capacity-limit-reached`, `limit`, `reason`, hint). The frontend retries a save refused this way (`persistence/busy-server-error?`).
  - `:mcp-update-file/by-profile` 1 permit, queue 5, timeout 60 s. A write never holds the owner's own save slot.
  - `:mcp-read/by-profile` 4 permits, queue 20, timeout 30 s.
  - `:mcp-read/global` 8 permits, queue 64, timeout 30 s.
  - `:mcp-find/by-file` 2 permits, queue 10, timeout 30 s. Taken by `find-mcp-shapes`, `find-mcp-connectors`, `get-mcp-fonts`, `get-mcp-page-lint`, `find-mcp-similar-boards`. Not by `get-mcp-subtree` or `get-mcp-interactions`.
- Call size (`mcp_limits.clj`): 2000 items per call (`max-changes`, `max-operations`); payload 8 MB transit; compiled changes capped by `:mcp-max-compiled-changes` (default 100000), checked for dry runs too. A call commits at most 50 batches of 2000 changes (`max-batches`, `notify-changes` in `mcp_write.clj`).
- SVG: text at most 8 MB (`schema:mcp-import-svg`). Parse failure: `:mcp-invalid-svg`.
- Tokens: `:mcp-token-max-age` default 90 days (`config.clj`). Applied only when a new MCP token has no explicit expiry (`access_token.clj`). Nil means no expiry.

## Compiler (in `common`)

- Operations are compiled in `common/src/app/common/mcp/operations.cljc` and `operations/`. Its rules (ops, `props` refusals, move refusals, default names) live there, not here.
- Compile output also holds `:op-results` (one entry per op, nil for most) and `:snapshot-hint`. `apply_operations` puts `:op-results` in the reply (`opResults`) when any is non-nil; `snapshot-wanted?` takes the hint (off with `snapshot: false`). A replay answers the `opResults` of the first answer (see Replay).
- `replace_font` (`operations/replace_font.cljc`) needs `:font-lookup` in the compile opts. The backend builds it (`app.rpc.mcp-font-lookup`, built on `mcp-fonts` `get-font-source`, `get-font-listing`, `get-font-reason` and `get-write-family`; no second index, no catalogue read when Google is off, team rows read lazily) only for a call that holds that op (`font-lookup-for` in `mcp_write.clj`). The op stamps `:modified-at` of the changed mains' components; the face of a node follows the renderer (own weight, nearest ancestor, own variant id, 400); the result has `auto-size-texts` (no resize); a copy with any text override keeps the old font after `sync_components`.

## Reads

- Page cache: `page-cache` in `mcp.clj`. Pointer pages are keyed by pointer id (fixed content, survives writes). Plain pages by file revn. Weight is the shape count; budget about 200,000 shapes; 10 min keepalive.
- Root cache: 10 min, 256 entries, keyed by file id, revn and vern. Outline cache: 10 min, 4096 entries.
- `get-mcp-page-tree` walk: `preorder-cache` in `mcp.clj` (10 min keepalive, weight = entries, budget 400000), keyed `[file-id page-id version root-id depth]`; later windows of a read cost no walk. `estimate-size` adds `total-shapes` and `estimated-bytes` (UTF-8 bytes of unescaped JSON; about 400 strata, one hash-picked shape each, version-seeded so it is deterministic; a sampled size above 20 sample medians counts once above that; `estimate-page-size`); only the adapter's whole-page load asks for it, never `get_page_tree`.
- `get-mcp-shapes` `include-children`: stored child order, all children of a shape before the descendants of its first child (`get-children-ids`), not the visual tree order; dangling child ids are left out. `include-ancestors`: ancestors of the requested ids up to the page root, first in the reply, top down, once each, inside the 2000/1 MB caps. The adapter's partial load (`execute_code` `rootIds`) uses both and rebuilds the tree order itself; the adapter asks for a loaded shape with no loaded child in place of its absent children (one call brings the children and their subtree), and keeps 2 calls in flight (the profile has 4 read permits); its fake in `SandboxHost.test.ts` mirrors this order and the backend test `shapes-with-children-come-in-stored-order-children-first` pins it.
- Cursors: base64 `[page-id version index root-id depth]`. Version is a pointer id or a revn. Wrong page, root or depth: `:mcp-invalid-cursor`. Version changed: `:mcp-stale-cursor`. Past end: `:mcp-invalid-cursor`.
- Reply budget: 1,000,000 bytes. A cut reply sets `truncated`; tree walks add `nextCursor`.
- Search: 5 s budget across pages; timeout sets `truncated`.
- `get-mcp-subtree`: `limit` 1-5000 (default 500), `max-bytes` 1000-1000000 (default 1 MB of transit text), or `max-json-bytes` 1000-4000000 (def `max-json-bytes` is the hard maximum; counts the JSON array of the window as the HTTP layer writes it, `json-size`, one comma per shape; both together: `:mcp-invalid-window`), `compact` (drops nil keys and `compact-defaults`: `hidden` false, `blocked` false, `opacity` 1, stroke alignment `center`; layout sizing stays; reply `compact` and `defaults`; `compact-defaults` must follow `mcp/with-defaults`, a test checks it). Root default is the page root (`uuid/zero`), skipped in the walk. Pre-order, stored child order, `depth` and `index`. Walk cached per (file, page, version, root) in `walk-cache` (keepalive 10 min, weight = entries, budget 400000). A repeated id is listed once and a missing id is skipped, so a cycle cannot loop. Cursor `[page-id version index root-id 0]`. Missing root: `:shape-not-found`. A window always keeps one shape.
- `get-mcp-interactions`: `limit` 1-5000 (default 1000), about 1 MB encoded. `flows` sorted by name, then id. `totalInteractions` and `totalShapes` count the whole page. Walk is cycle-safe (`get-walk-entries`). `overlay-position` is a point map `{x, y}`.
- `find-mcp-shapes`: the 5 s budget starts after the first page is loaded and a call examines at least one shape. An early end returns the matches so far with `truncated`, `reason` (`size`|`limit`|`time`), `scanned` and `next-cursor` (a page-tree-shaped cursor: page, version, entry index, root, and in the depth slot a packed hash of the filters and of the ordered page ids: other filters = `:mcp-invalid-cursor`, other pages = `:mcp-stale-cursor`; `cursor` param). `skipped` and `skipped-ids` (at most 20) only when a call dropped a shape whose name regex timed out first. `skipped-large` and `skipped-large-ids` (at most 20) when a match alone is over the byte budget: the call leaves it out and the cursor goes past it (`fit-matches`). `max-bytes` (1000-1,000,000) caps the matches as UTF-8 bytes of their JSON (`json-size`, 512 bytes kept for the envelope: `find-reply`); the adapter sends 85 % of its response cap. The scan keeps a running byte count (`match-fit`, shared with `fit-matches`) and stops at the first match that fits alone but not with the held ones; that shape is scanned again as the first of the next call, so a walk that ends by size each call has sum(`scanned`) = shapes visited + calls - 1. `get-mcp-shapes` `fields` also takes `text-layout-state` and `characters` (`derived-shape-attr-names`).
- `find-mcp-connectors`: `max-distance` 0-2000 (default 64), `limit` 1-2000 (default 500), `offset` >= 0 (default 0), `within-id` (not on page: `:shape-not-found`), `depth`/`mode`/`board-name-regex` (as the lint; own copy of the regex helpers, `mcp-lint` keeps them private), `include-same-screen`. Screens = `mcp-boards/select-boards` ids. Frame snap: all visible frames, `shape-rect`, read through a 512 px grid (`build-board-index`, `find-snap-board`; `snap-among` is the plain reference that the test compares); `board-id`/`board-name`. The screen of an end is resolved apart (`get-targets`, `build-target-index`, `resolve-target`): targets = selected boards + loose frames (visible, not selected, not inside a selected board); a frame that holds a selected board is never a target. Nearest target within `max-distance` by `board-dist2` (grid of 512 px cells, `:big` list for huge boxes); tie: screen, smaller area, walk order. Screen: `screen-id`/`screen-name`; loose frame or none: `non-screen true`. Gate: both frames snap, and the targets differ; same screen target + different frames = same-screen; same target + same frame = silent drop; a missing target falls back to different frames. An end with no frame (an arrow that is a child of a screen) is kept when both ends have targets and they differ (the target stands in for `board-id`/`board-name`); same screen target with no frames = same-screen (counted). Same-screen connectors dropped and counted (`same-screen-skipped`), `non-screen-ends` counts ends. Reply `selection`, `deeper-boards` only when non-nil. Candidates `:path`, `:bool` and composed groups (`composed-group?`: 2-6 visible drawing children, box elongated 3x or side <= 24, and the anatomy of one arrow, `composed-anatomy?`: one shaft >= 0.7 of the long side, every other child within 2 shaft widths of a shaft end; otherwise the children are candidates; children of an arrow group are not). Known limit: a rect is a candidate only inside a group; an arrow with a shaft split in two, or a label rect in the group, is no arrow, and only its head path stays a candidate, shallowest first. A candidate inside its nearest frame that holds no frame is skipped early and not counted (`inside-own-frame?`). Direction (pure fns on plain points, thresholds are public defs): open stroked path = cap rule (`high`), else `none`; outlines = `flatten-content` (8 per curve, `curve-values`) -> `simplify-ring` (bounded error: a point is dropped only if all points dropped since the last kept one stay within 0.05 px of the chord) -> `shaft-width` (2A/P; a ring wholly inside another is a hole, its area subtracted) -> `find-head-tips` (hull, angle <= 80, edges >= 1.2w, directional extremity: no point beyond the tip along its outward bisector by > 10 % of the extent; the brief said centroid distance, which cannot hold for a symmetric arrow and rejects a V) -> 1 tip `shape` (`high` at angle <= 60 and width >= 1.5w within 3w, else `medium`); 2+ tips: `both` only if the two farthest apart point opposite ways (dot < -0.5) and sit within 10 % of the extent of the ends, else one head = the tip with the longest `:reach`; 0 sharp tips: rule 2 (`capped-tip-at`: two hull edges >= 1.2w around a cap < 0.75w, lines meeting at 20-100 degrees, tip = middle of the cap; wide tip: angle 80-100; rule 2 needs an outline >= 4w long and a tip whose inward bisector is within 20 degrees (`tip-axis-angle`, `on-axis?`) of the line to the farthest outline point, so rectangles and V shapes get no tip), always `medium`; none: direction `none`, confidence `none`, ends = two farthest points (the old width test is gone; `low` does not occur). A shape whose head cannot be read has direction `none`: callers take the direction from other evidence (labels, screen order). `composed-direction` pools the children rings, shaft = best length/width ratio, tips on the shaft ignored. Capped tips and `both` need an elongated outline (length >= 4 w), so a rounded square has no tip and a play triangle is one head. Known: a flat rhombus reads `both`; a rounded tip of radius w/2 and a blunt tip wider than 0.75w are not read (direction `none`). 5 s budget (`search-budget-ns`) is checked in the board selection and the scan loop only; frames, grids and candidates are linear and unchecked. `length` = straight distance. Paging: `scan-connectors` scans every candidate (no stop at `limit`; order = level, then walk order, stable), the command slices `offset`..`offset`+`limit`. Reply `total` = all found; `same-screen-skipped`, `non-screen-ends` and `total` cover all of them, not the page. `next-offset` only when items remain; offset past the end: empty list, no `next-offset`. `truncated` = items remain or time cut; `timed-out true` (only then present) = the scan or the selection ran out of time (`total` is then what was found) and `next-offset` is left out (each call selects under its own clock, so a later page could differ). The adapter (`FindConnectorsTool`) fits whole items to its cap with `BackendTool.formatPagedJson` and sets `nextOffset` itself.
- `get-mcp-fonts`: `root-ids` 1-200, needs `page-id`. Usage cached per page key in `usage-cache` (10 min, weight = fonts, budget 200000); resolution read on every call (`get-font-context`). Without `page-id`: 5 s budget (`scan-budget-ns`), first page always read, `complete` false when cut. Reply at most 500 fonts and within the response budget; `unresolved` counts all fonts. Runs of one face merge under the listed variant id (`get-variant-reports`). Empty text leaves are not runs (`get-text-runs`). Google catalogue `common/resources/fonts/gfonts.2025.11.28.json` via `fonts/load-gfonts` in a `delay`; a read failure is logged once and the index is empty. Reasons: `google-fonts-disabled`, `not-in-google-catalog`, `custom-font-not-in-team`, `unknown-font-id`, `variant-not-found`. A variant of an unresolved font takes the font's reason.
- Board selection (`app.rpc.mcp-boards`, pure; shared by `get-mcp-page-lint`, `find-mcp-similar-boards`, `find-mcp-connectors`): `select-boards objects {:depth :mode :name-match :deadline}` returns `{:ids :timed-out? :deeper-boards :selection}` (`:deeper-boards` nil in `auto`). Params `depth` 1-12, `mode` `depth`|`auto`. No `depth`, regex or `mode`: `auto`. `depth` or regex alone: `depth` (default 1, component frames included). `auto` + `depth`: `:mcp-invalid-board-selection`. `auto` + regex: filter after the selection. One full walk (`walk-frames`: level, `comp?`, size, ancestor set; deadline every 256 entries).
- `auto` (`select-auto`): candidates are visible, outside components, level 1-12, both sides >= `min-screen-side` (200). Size classes within 2 px of the first member (`group-size-classes`), qualify at 3 members; only the 50 largest qualifying classes are weighed (`max-qualifying-classes`); deadline checked in `select-auto` and `remove-container-layers` (timeout: fallback with `:timed-out?`). `standard-size?`: exact match in both orientations of a `standard-sizes` entry, or same width and taller for an entry in its LISTED orientation. `standard-classes`: standard qualifying classes, minus any inside another standard class or inside any class with MORE members (a one-to-one wrapper does not hide the screens). A class standard only by the taller rule is a wrapper class (`wrapper-classes`; not chosen, hides nothing, `other-sizes` relation `wrapper`) when an exact standard class (`exact-standard-size?`) of the same width exists with `wrapper-height-ratio` (1.25) >= tall/exact > 1 and more than half of the wrapper's frames hold exactly one frame of the exact class (any ancestor depth, so nested wrappers work); 800x660 `State` around 800x600 `Parent` is one, 390x2000 around 390x844 is not; some left: `basis` `standard-size`. Else structure (`get-inside-map`, `remove-container-layers`, area guard 10 %): `basis` `structure`. Then `drop-nested` (different classes: inner goes; same-class chain of nested boards: ONE stays: (1) with a name regex in mode auto the outermost matching one via `name-ok?` (`:timeout` = no match), (2) else the member whose exact name is borne by the most BARE boards of the class (in no chain; >= 1; tie: outermost; default names `Board`/`Frame [n]` (`default-frame-name`) do not count), (3) else the outermost; if 1 or 2 leaves several outermost (siblings) the chain top stays, so exactly one per chain; `selection.nested-same-size` counts kept boards of chains that had other members, only when > 0; walk entries carry `:name`), loose boards (candidates not above or below a board, level <= shallowest, area >= 10 % of largest class). Nothing: depth 1, `fallback` true, `basis` `depth-fallback`. Known: non-standard screens with equal sections or wrappers give the sections; non-standard screens that hold as many or more standard mockups or dialogs than screens give the mockups or dialogs. `selection` `{mode depth? fallback? basis? sizes sizes-omitted other-sizes boards min-depth max-depth}`; `other-sizes` (auto): up to 5 qualifying classes with no selected board, `{width height boards relation}` (`inside`/`outside` the selected boards, or `wrapper` for a wrapper class). `deeper-boards` (depth mode only, nil in auto, key left out of replies): frames below the selected boards that are candidates in a class of >= 3 members.

## Idempotency

- `request-id` (optional, UUID). Without one, the server makes a fresh id, so no replay protection.
- Session id = UUID of `penpot-mcp:<token-id>:<request-id>:<digest>`. The digest is the SHA-256 of the canonical text of the payload (`payload-of`: `changes`, `operations`, `page-id`, `parent-id`, `svg`, `x`, `y`, `name`, `allow-split`, `snapshot`). The token id is part of it, so another token cannot replay. A reused request id with another payload gets another session id: a new write.
- Replay: checked under the file lock, before the compile (`applied-before?`). If the file has change rows with that session id, the answer is `already-applied: true`, `commits: 0`, the counts from the old rows. Nothing is written or notified. The reply data (`created-ids`, `op-results`, `root-id`, `shape-ids`) lives in the `mcp_reply` column (migration `0160`, nullable bytea) of the first change row of the call (`replay-reply`, `stored-reply`; `files-update` `::reply` on the first batch). Never in `data`: that is the legacy-backend column, and `files.clj` `sql:restore-file-changes` clears `deleted_at` on every row with `data`, so the reply row would never expire. Only `stored-reply` selects it. Caps: 10,000 entries per list, 1 MiB encoded; over that, `op-results` goes first, then half of the ids at a time, and the replay says `replay-truncated`. A record with no data (made before this) answers without them.
- Window: change rows get `deleted_at` = commit + 1 h (`files_update.clj`). The objects GC deletes them after that. A retry after that window applies again.
- Dry runs skip the replay check.
